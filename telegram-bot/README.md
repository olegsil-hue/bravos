# Football Heroes — Telegram-бот + веб-приложение (общая база)

Еженедельный опрос → деление на команды → апрув → запись игр. С версии
с общей базой этот сервис отдаёт **и** самого Telegram-бота, **и**
веб-приложение (`public/index.html`) на одном и том же порту — оба
читают/пишут ОДНУ SQLite-базу через `src/db.js`. Правки в вебе (роспись,
рейтинги, игровые дни) сразу видны боту и наоборот, без ручного переноса.

**Как открыть веб-приложение:** та же ссылка, что у бота на Railway
(Settings → Networking → Public Domain; если домена ещё нет — там же
«Generate Domain»). Старый артефакт на claude.ai — замороженный снимок,
больше не обновляется и не связан с этой базой.

**Реализовано сейчас:**
1. Каждый **понедельник в 09:00** бот сам публикует опрос «Футбол в среду
   в 19:00 (до 15 человек)» с вариантами «Буду» / «Не смогу» в групповой
   чат — не дожидаясь команды от админа (если такой уже есть открытый —
   не дублирует). `/poll` (только админ) — то же самое вручную, если
   нужно раньше понедельника.
2. Каждую **среду в 12:00** бот сам закрывает последний открытый опрос,
   делит проголосовавших «Буду» на 2 команды (≤10 человек) или 3 (11–15),
   и присылает состав вам в личку с кнопками «Утвердить» / «Пересчитать».
3. После утверждения состав сохраняется и объявляется в группе.
4. Каждую **среду в 18:00** бот открывает запись игр в группе (или раньше —
   `/start_game`, доступно **любому участнику группы**, не только админу:
   на игре не всегда есть время ждать конкретного человека). Если команд
   3 и больше — сначала спрашивает кнопками, **какая пара играет первой**
   (К1–К2, К1–К3 или К2–К3 — все варианты, тоже может нажать кто угодно),
   оставшаяся команда отдыхает в Игре 1. Для 2 команд выбирать нечего —
   старт сразу. После выбора — «Игра 1» с кнопками «⚽ Гол: Команда N» для
   каждой из двух играющих команд — жать эти кнопки, выбирать автора гола
   и паса тоже может любой участник группы. Кнопка «🏁 Матч окончен»
   фиксирует счёт; если он не ничейный, **проигравшая команда уступает
   место** той, что отдыхала — так же, как в исходном формате «победитель
   остаётся». При ничьей бот спрашивает, был ли победитель по пенальти
   (или оставляет как есть). Есть кнопка «↩️ Отменить последний гол» на
   случай опечатки. Для 2 команд ротации нет — Игра 2 начинается между
   теми же двумя.
5. `/end_day` (тоже доступно любому участнику группы) — завершает игровой
   день и присылает итоги **тремя картинками** (итоговая таблица, полный
   журнал игр, личная статистика — как в приложении) альбомом, и в личку
   тому, кто вызвал команду, и в группу. Отрисовка — своя (SVG → PNG через
   `sharp`, без headless-браузера, см. `src/imageReport.js`), поэтому не
   пиксель-в-пиксель с веб-версией, но тот же стиль (тёмная шапка, цвета
   команд, медали) и те же данные. Если отрисовка вдруг упадёт —
   автоматически откатывается на текстовый вариант, чтобы `/end_day` не
   проваливался целиком.

## Деплой на Railway (рекомендованный вариант)

1. **Создайте бота**: в Telegram напишите **@BotFather** → `/newbot` →
   следуйте подсказкам → скопируйте токен вида `123456:ABC-...`.
2. **Узнайте свой Telegram user id**: напишите **@userinfobot** → он
   пришлёт ваш `id`.
3. **Добавьте бота в вашу группу** (ту, где будет идти опрос и запись игр),
   дайте ему право отправлять сообщения.
4. **Узнайте id группы**: отправьте в группу любое сообщение, затем
   откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите
   `"chat":{"id": -100...}` — это отрицательное число, оно и есть
   `TELEGRAM_GROUP_CHAT_ID`.
5. **Railway**: зайдите на [railway.app](https://railway.app), заведите
   аккаунт (можно через GitHub), **New Project → Deploy from GitHub repo**,
   выберите этот репозиторий, укажите **Root Directory: `telegram-bot`**.
6. В настройках проекта на Railway откройте **Variables** и добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1
   - `TELEGRAM_GROUP_CHAT_ID` — id из шага 4
   - `TELEGRAM_ADMIN_USER_ID` — ваш id из шага 2
   - `TIMEZONE` — `Europe/Moscow` (или другой, если нужно)
7. Добавьте **Volume** (Railway → Settings → Volumes), примонтируйте на
   путь `/app/data` — это постоянное хранилище для файла SQLite, чтобы
   данные не терялись при перезапуске. Переменную `DB_PATH` при этом можно
   не трогать (по умолчанию `./data/football.db`).
8. Railway сам подхватит `npm start` из `package.json` и запустит бота.
   В логах должно появиться `Бот запущен.`.

## Деплой на свой VPS (Timeweb Cloud и похожие)

В отличие от Railway это не «пуш — само задеплоилось»: понадобится
завести сервер и один раз настроить его руками. Зато без сюрпризов с
оплатой — обычный тариф VPS, известная фиксированная цена. Шаги 1-4
(токен бота, свой id, добавить в группу, id группы) — те же, что в
разделе Railway выше, дальше отличается.

1. **Создайте облачный сервер** на [timeweb.cloud](https://timeweb.cloud):
   ОС — **Ubuntu 22.04 LTS**, минимальный тариф (1 CPU / 1 ГБ ОЗУ)
   достаточно. Запишите **IP-адрес** и пароль root (или подключите свой
   SSH-ключ при создании).
2. **Подключитесь по SSH** с компьютера:
   ```bash
   ssh root@ВАШ_IP
   ```
3. **Установите Node.js 20, git и инструменты сборки** (нужны для
   нативных модулей `better-sqlite3`/`sharp`):
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
   apt-get install -y nodejs git build-essential python3
   ```
4. **Склонируйте репозиторий и поставьте зависимости**:
   ```bash
   cd /opt
   git clone https://github.com/olegsil-hue/bravos.git
   cd bravos/telegram-bot
   git checkout claude/football-heroes-team-division-5p4jqx
   npm ci --omit=dev
   ```
5. **Настройте переменные окружения**:
   ```bash
   cp .env.example .env
   nano .env
   ```
   Заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_GROUP_CHAT_ID`,
   `TELEGRAM_ADMIN_USER_ID`, `TIMEZONE`. `DB_PATH` и `PORT` можно оставить
   по умолчанию (`./data/football.db` и `3000`) — на обычном VPS диск
   и так постоянный, отдельный «Volume», как на Railway, не нужен.
6. **pm2** — держит процесс запущенным и поднимает после перезагрузки
   сервера:
   ```bash
   npm install -g pm2
   pm2 start src/index.js --name football-heroes
   pm2 save
   pm2 startup   # выполните команду, которую он выведет
   ```
7. **nginx** — чтобы открыть сайт по адресу `http://ВАШ_IP/` (порт 80),
   а не `:3000`, и один процесс мог слушать 80-й порт без root-прав у
   Node:
   ```bash
   apt-get install -y nginx
   cat > /etc/nginx/sites-available/football-heroes <<'EOF'
   server {
       listen 80;
       server_name _;
       location / {
           proxy_pass http://localhost:3000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   EOF
   ln -s /etc/nginx/sites-available/football-heroes /etc/nginx/sites-enabled/
   rm -f /etc/nginx/sites-enabled/default
   systemctl restart nginx
   ```
8. **Файрвол** — откройте 22 (SSH) и 80 (сайт); проверьте и облачный
   файрвол в панели Timeweb, если он включён отдельно:
   ```bash
   ufw allow 22
   ufw allow 80
   ufw enable
   ```
9. Откройте `http://ВАШ_IP/` в браузере — должно открыться приложение.
   Бот отвечает в Telegram сразу же (long polling не требует открытых
   портов, только исходящий доступ к `api.telegram.org` — на обычном VPS
   он обычно есть).

**Обновление после новых правок в репозитории:**
```bash
cd /opt/bravos/telegram-bot
git pull
npm ci --omit=dev
pm2 restart football-heroes
```

**HTTPS (по желанию, если заведёте домен):** направьте домен на IP
сервера (A-запись), затем `apt-get install -y certbot python3-certbot-nginx`
и `certbot --nginx -d ваш-домен.ру` — сертификат Let's Encrypt настроится
в nginx автоматически. Без домена (просто по IP) выпустить настоящий
HTTPS-сертификат нельзя — это ограничение Let's Encrypt, не Timeweb.

## Первое использование

1. **Регистрация игроков — без ручного /register для каждого.** В
   веб-приложении (вкладка «Игроки») у каждого игрока есть поля «Telegram
   username» и «Отображаемое имя в Telegram» — заполните хотя бы одно
   (без «@» в username). Скопируйте строки из «Массовый ввод/экспорт»
   (9 столбцов, username и отображаемое имя — два последних) и отправьте
   боту от админа:
   ```
   /set_usernames
   Иван Петров; DEF; MID; 4; 7; 6; 5; ivan_petrov; Ваня П 🏃
   Сергей Орлов; GK; ; 8; 4; 3; 5; sergey_orlov;
   ```
   ```
   /set_display_names
   Иван Петров; DEF; MID; 4; 7; 6; 5; ivan_petrov; Ваня П 🏃
   Сергей Орлов; GK; ; 8; 4; 3; 5; sergey_orlov;
   ```
   Обе команды берут из вставленной строки только свой столбец (username —
   8-й, отображаемое имя — 9-й; остальные поля игнорируются) — можно
   отправить один и тот же текст в обе команды. Короткая форма построчно
   тоже работает: `Имя; username` или `Имя; Отображаемое имя`. После этого
   бот узнаёт игрока **автоматически при первом голосовании** в опросе —
   `/register` не нужен.

   **Если у игрока вообще нет `@username`** (частый случай) — отображаемое
   имя (то, что видно в чате или в «Poll Results», может быть любым ником
   с эмодзи) выступает запасным способом. Оба способа проверяются при
   голосовании автоматически (сначала
   username, потом отображаемое имя). `/register Имя Фамилия` остаётся
   как ручной запасной вариант для тех, кого ни то, ни другое не поймало.
2. Вы (админ) отправляете боту в личке `/poll`, когда решите открыть запись
   на игру.
3. В среду в 12:00 бот сам всё посчитает и пришлёт вам состав на апрув. Чтобы
   проверить это раньше среды — используйте `/divide_now` (только админ):
   закрывает последний открытый опрос и сразу присылает деление на апрув.
   **Важно:** `/divide_now` без аргумента и `/status` работают с
   **последним СОЗДАННЫМ** открытым опросом — если открытых опросов
   оказалось несколько (например, случайно оставленный тестовый), это
   может быть не тот, где реальные голоса. Проверьте `/polls` (список
   всех опросов с числом голосов) и, если нужно, укажите конкретный:
   `/divide_now 3` (просто число id после команды через пробел, без
   скобок). Если открытых опросов вообще нет — сначала снова `/poll`.
   Голос, поданный **до** того как игроку занесли username (или до
   обновления бота), тоже не потеряется: перед подсчётом бот пробует
   довязать таких проголосовавших, спросив у Telegram их username по id.
4. После вашего «✅ Утвердить» состав сохранён. В среду в 18:00 бот сам
   откроет запись игр в группе. Открыть раньше 18:00 — `/start_game` в
   группе (доступно любому участнику, не только вам).
5. Когда наигрались — `/end_day` (тоже доступно любому участнику)
   присылает итоги дня.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | приветствие |
| `/register Имя Фамилия` | все | привязать себя к игроку из списка (запасной вариант, если username не сработал) |
| `/players` | все | список всех игроков (с username, если указан) |
| `/set_usernames` + строки | админ | массово привязать Telegram username → игрок (без /register для каждого) |
| `/set_display_names` + строки | админ | то же, но по отображаемому имени в Telegram — для игроков без `@username` |
| `/poll` | админ | опубликовать опрос в группе |
| `/status` | админ | сколько уже ответили на текущий (последний созданный) опрос |
| `/polls` | админ | список всех опросов с числом голосов — если открытых оказалось несколько |
| `/simulate_votes [N]` | админ | дозаполнить опрос N (по умолчанию 9) случайными игроками — не трогает реальные голоса, для теста без сбора живых людей |
| `/divide_now [id]` | админ | закрыть опрос (по умолчанию — последний созданный открытый, либо конкретный по id из `/polls`) и прислать деление на апрув сейчас |
| `/manual_divide` + имена | админ | занести состав «Буду» вручную (имена по одному на строке) и сразу прислать деление на апрув — для опроса, созданного не через `/poll` (бот не видит голоса по чужим опросам) |
| `/start_game` | все | открыть запись игр сейчас (не ждать среды 18:00) |
| `/end_day` | все | завершить день и прислать итоговую статистику (картинками) |
| `/days` | админ | список игровых дней с id (найти тестовый, чтобы удалить) |
| `/delete_day 20` | админ | удалить игровой день целиком, id числом (для очистки тестовых прогонов) |

## Как протестировать запись игры (без реального опроса и 9+ человек)

Всё — на боевом боте, но без реальных данных: после теста тестовый
игровой день удаляется, история и статистика реальных игр не трогаются.

1. `/manual_divide`, дальше — 4–6 любых имён из `/players` (реальных
   игроков, не тестовых — состав только для проверки механики):
   ```
   /manual_divide
   Иван Петров
   Сергей Орлов
   ...
   ```
   Придёт состав на апрув в личку — нажмите **✅ Утвердить**.
2. `/start_game` (в личке или в группе) — откроет «Игра 1» с кнопками
   «⚽ Гол: Команда N».
3. Нажмите кнопку гола за любую команду → выберите игрока-автора → пас
   (или «Без паса»). Голы фиксируются сразу, «↩️ Отменить последний гол»
   исправляет опечатку.
4. «🏁 Матч окончен» — при неничейном счёте проигравшая команда уступает
   место (для 3 команд), появляется «Игра 2» с новым составом. Запишите
   пару матчей, чтобы проверить ротацию.
5. `/end_day` — пришлёт итоговую таблицу и личную статистику дня (то, что
   в проде уходит и в личку, и в группу).
6. Уберите тестовые данные: `/days` → найдите id только что созданного
   дня (он самый свежий, в самом верху списка) → `/delete_day 20` (просто
   число, без скобок).

## Общая база с веб-приложением

`src/server.js` — Express-сервер: отдаёт `public/index.html` статикой и
два эндпоинта, `GET/POST /api/state`, читающих/пишущих ту же SQLite, что
использует сам бот (`db.getRoster()`/`db.getAllGameDaysForStats()` на
чтение, `db.replaceState(roster, gameDays)` на запись — полная замена
ростера по имени и игровых дней по id, кроме `status` игрового дня и
связанных `live_matches`, если он уже управляется ботом — веб-приложение
про это не знает и не должно перезатирать). Запускается в том же
процессе, что и сам бот (`index.js`, «Шаг 0/3» перед стартом поллинга),
на порту из `PORT` (Railway подставляет сама).

`public/index.html` — та же логика, что в `football-heroes-live.html`
(деление на команды, рейтинг, игровые дни, статистика), но слой
хранения переписан: `loadData()`/`saveData()` вместо localStorage
делают `fetch('/api/state')` — то же самое действие, что раньше искали
руками при каждой правке через известные-сопоставления-файлы. Раздаётся
с того же origin, что и API — CORS не нужен, а песочница артефактов
claude.ai (с её жёстким CSP на внешние хосты) тут ни при чём, страница
больше не живёт в артефакте.

**Разовая миграция** (`src/full-state-migration.json` +
`runFullStateMigrationIfNeeded()` в `db.js`): снимок актуальных данных
из `football-heroes-live.html` на момент перехода на общую базу.
Выполняется ровно один раз за всё время жизни базы (флаг в таблице
`schema_meta`) — если база уже содержит данные (обычный случай на уже
работающем боте), полностью их заменяет этим снимком **один раз**, и
дальше уже сама база (через `/api/state`) — источник правды. Если файла
нет — миграция считается неприменимой и просто помечается выполненной.

`src/seed-data.json` — старый снимок для `seedIfEmpty()` (когда база
физически пустая, например самый первый запуск без Volume) — актуален
только пока не сработала миграция выше; после неё не используется.

`src/known-telegram-names.json` — отдельный список известных
сопоставлений Telegram username/displayName → игрок, разобранных
вручную из скриншотов реальных опросов (Poll Results), а не введённых
через `/set_usernames`/`/set_display_names`. Применяется автоматически

кто-то не забудет заново продиктовать их боту в чат. Никогда не

кто-то не забудет заново продиктовать их боту в чат. Никогда не
перезаписывает значение, если оно уже задано в базе (через сами эти
команды или ранее применённый список) — админ всегда приоритетнее.

`src/known-roster-factor-overrides.json` — то же самое, но для факторов
GK/DEF/ATT/END: ручные правки, сделанные в веб-версии, руками
переносятся сюда, чтобы бот считал рейтинг так же. В отличие от
известных Telegram-имён, здесь значения **всегда перезаписываются** при
каждом запуске (не только если пусто) — это подправленные актуальные
цифры из веб-версии, а не запасной вариант.
