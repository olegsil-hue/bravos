# Football Heroes — Telegram-бот

Еженедельный опрос → деление на команды → апрув. Использует ту же логику
деления и формулу рейтинга, что и `football-heroes-live.html` (см.
`src/core/`), но со своей базой SQLite вместо localStorage браузера — это
и есть общий источник данных, доступный боту.

**Реализовано сейчас:**
1. `/poll` (только админ) — публикует опрос «Футбол в среду в 19:00 (до 15
   человек)» с вариантами «Буду» / «Не смогу» в групповой чат.
2. Каждую **среду в 12:00** бот сам закрывает последний открытый опрос,
   делит проголосовавших «Буду» на 2 команды (≤10 человек) или 3 (11–15),
   и присылает состав вам в личку с кнопками «Утвердить» / «Пересчитать».
3. После утверждения состав сохраняется и объявляется в группе.
4. Каждую **среду в 18:00** бот открывает запись игр в группе. Если команд
   3 и больше — сначала спрашивает кнопками, **какая пара играет первой**
   (К1–К2, К1–К3 или К2–К3 — все варианты), оставшаяся команда отдыхает
   в Игре 1. Для 2 команд выбирать нечего — старт сразу. После выбора —
   «Игра 1» с кнопками «⚽ Гол: Команда N» для каждой из двух играющих
   команд. При
   нажатии — выбор игрока-автора гола, затем игрока-ассистента (или «Без
   паса»). Кнопка «🏁 Матч окончен» фиксирует счёт; если он не ничейный,
   **проигравшая команда уступает место** той, что отдыхала — так же, как
   в исходном формате «победитель остаётся». При ничьей бот спрашивает,
   был ли победитель по пенальти (или оставляет как есть). Есть кнопка
   «↩️ Отменить последний гол» на случай опечатки. Для 2 команд ротации
   нет — Игра 2 начинается между теми же двумя.
5. `/end_day` (только админ) — завершает игровой день и присылает итоги
   текстом: итоговую таблицу (И/В/Н/П/голы/очки, как на вкладке «Игровые
   дни» веб-приложения) и личную статистику (голы/передачи) за день — и в
   личку, и в группу.

**Известное упрощение:** итоги приходят как отформатированный текст, а не
как картинки-скриншоты (как в примере с тремя фотографиями) — генерация
изображений на сервере бота потребовала бы headless-браузера, это
отдельная задача, если нужна визуальная идентичность с веб-версией.

## Деплой на Railway (рекомендованный вариант)

1. **Создайте бота**: в Telegram напишите **@BotFather** → `/newbot` →
   следуйте подсказкам → скопируйте токен вида `123456:ABC-...`.
2. **Узнайте свой Telegram user id**: напишите **@userinfobot** → он
   пришлёт ваш `id`.
3. **Добавьте бота в вашу группу** (ту, где будет идти опрос и запись игр),
   дайте ему право отправлять сообщения.
4. **Узнайте id группы**: отправьте в группу любое сообщение, затем
   откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите
   `"chat":{"id": -100...}` — это отрицательное число, оно и есть
   `TELEGRAM_GROUP_CHAT_ID`.
5. **Railway**: зайдите на [railway.app](https://railway.app), заведите
   аккаунт (можно через GitHub), **New Project → Deploy from GitHub repo**,
   выберите этот репозиторий, укажите **Root Directory: `telegram-bot`**.
6. В настройках проекта на Railway откройте **Variables** и добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1
   - `TELEGRAM_GROUP_CHAT_ID` — id из шага 4
   - `TELEGRAM_ADMIN_USER_ID` — ваш id из шага 2
   - `TIMEZONE` — `Europe/Moscow` (или другой, если нужно)
7. Добавьте **Volume** (Railway → Settings → Volumes), примонтируйте на
   путь `/app/data` — это постоянное хранилище для файла SQLite, чтобы
   данные не терялись при перезапуске. Переменную `DB_PATH` при этом можно
   не трогать (по умолчанию `./data/football.db`).
8. Railway сам подхватит `npm start` из `package.json` и запустит бота.
   В логах должно появиться `Бот запущен.`.

## Первое использование

1. **Регистрация игроков — без ручного /register для каждого.** В
   веб-приложении (вкладка «Игроки») у каждого игрока есть поля «Telegram
   username» и «Отображаемое имя в Telegram» — заполните хотя бы одно
   (без «@» в username). Скопируйте строки из «Массовый ввод/экспорт»
   (9 столбцов, username и отображаемое имя — два последних) и отправьте
   боту от админа:
   ```
   /set_usernames
   Иван Петров; DEF; MID; 4; 7; 6; 5; ivan_petrov; Ваня П 🏃
   Сергей Орлов; GK; ; 8; 4; 3; 5; sergey_orlov;
   ```
   ```
   /set_display_names
   Иван Петров; DEF; MID; 4; 7; 6; 5; ivan_petrov; Ваня П 🏃
   Сергей Орлов; GK; ; 8; 4; 3; 5; sergey_orlov;
   ```
   Обе команды берут из вставленной строки только свой столбец (username —
   8-й, отображаемое имя — 9-й; остальные поля игнорируются) — можно
   отправить один и тот же текст в обе команды. Короткая форма построчно
   тоже работает: `Имя; username` или `Имя; Отображаемое имя`. После этого
   бот узнаёт игрока **автоматически при первом голосовании** в опросе —
   `/register` не нужен.

   **Если у игрока вообще нет `@username`** (частый случай) — отображаемое
   имя (то, что видно в чате или в «Poll Results», может быть любым ником
   с эмодзи) выступает запасным способом. Оба способа проверяются при
   голосовании автоматически (сначала
   username, потом отображаемое имя). `/register Имя Фамилия` остаётся
   как ручной запасной вариант для тех, кого ни то, ни другое не поймало.
2. Вы (админ) отправляете боту в личке `/poll`, когда решите открыть запись
   на игру.
3. В среду в 12:00 бот сам всё посчитает и пришлёт вам состав на апрув. Чтобы
   проверить это раньше среды — используйте `/divide_now` (только админ):
   закрывает последний открытый опрос и сразу присылает деление на апрув.
   **Важно:** `/divide_now` без аргумента и `/status` работают с
   **последним СОЗДАННЫМ** открытым опросом — если открытых опросов
   оказалось несколько (например, случайно оставленный тестовый), это
   может быть не тот, где реальные голоса. Проверьте `/polls` (список
   всех опросов с числом голосов) и, если нужно, укажите конкретный:
   `/divide_now <id>`. Если открытых опросов вообще нет — сначала снова
   `/poll`.
   Голос, поданный **до** того как игроку занесли username (или до
   обновления бота), тоже не потеряется: перед подсчётом бот пробует
   довязать таких проголосовавших, спросив у Telegram их username по id.
4. После вашего «✅ Утвердить» состав сохранён. В среду в 18:00 бот сам
   откроет запись игр в группе. Проверить раньше 18:00 — `/start_game`
   (только админ) в группе.
5. Когда наигрались — `/end_day` (только админ) присылает итоги дня.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | приветствие |
| `/register Имя Фамилия` | все | привязать себя к игроку из списка (запасной вариант, если username не сработал) |
| `/players` | все | список всех игроков (с username, если указан) |
| `/set_usernames` + строки | админ | массово привязать Telegram username → игрок (без /register для каждого) |
| `/set_display_names` + строки | админ | то же, но по отображаемому имени в Telegram — для игроков без `@username` |
| `/poll` | админ | опубликовать опрос в группе |
| `/status` | админ | сколько уже ответили на текущий (последний созданный) опрос |
| `/polls` | админ | список всех опросов с числом голосов — если открытых оказалось несколько |
| `/simulate_votes [N]` | админ | дозаполнить опрос N (по умолчанию 9) случайными игроками — не трогает реальные голоса, для теста без сбора живых людей |
| `/divide_now [id]` | админ | закрыть опрос (по умолчанию — последний созданный открытый, либо конкретный по id из `/polls`) и прислать деление на апрув сейчас |
| `/manual_divide` + имена | админ | занести состав «Буду» вручную (имена по одному на строке) и сразу прислать деление на апрув — для опроса, созданного не через `/poll` (бот не видит голоса по чужим опросам) |
| `/start_game` | админ | открыть запись игр сейчас (не ждать среды 18:00) |
| `/end_day` | админ | завершить день и прислать итоговую статистику |
| `/days` | админ | список игровых дней с id (найти тестовый, чтобы удалить) |
| `/delete_day <id>` | админ | удалить игровой день целиком (для очистки тестовых прогонов) |

## Как протестировать запись игры (без реального опроса и 9+ человек)

Всё — на боевом боте, но без реальных данных: после теста тестовый
игровой день удаляется, история и статистика реальных игр не трогаются.

1. `/manual_divide`, дальше — 4–6 любых имён из `/players` (реальных
   игроков, не тестовых — состав только для проверки механики):
   ```
   /manual_divide
   Иван Петров
   Сергей Орлов
   ...
   ```
   Придёт состав на апрув в личку — нажмите **✅ Утвердить**.
2. `/start_game` (в личке или в группе) — откроет «Игра 1» с кнопками
   «⚽ Гол: Команда N».
3. Нажмите кнопку гола за любую команду → выберите игрока-автора → пас
   (или «Без паса»). Голы фиксируются сразу, «↩️ Отменить последний гол»
   исправляет опечатку.
4. «🏁 Матч окончен» — при неничейном счёте проигравшая команда уступает
   место (для 3 команд), появляется «Игра 2» с новым составом. Запишите
   пару матчей, чтобы проверить ротацию.
5. `/end_day` — пришлёт итоговую таблицу и личную статистику дня (то, что
   в проде уходит и в личку, и в группу).
6. Уберите тестовые данные: `/days` → найдите id только что созданного
   дня (он самый свежий, в самом верху списка) → `/delete_day <id>`.

## Локальный запуск для проверки

```bash
cd telegram-bot
npm install
cp .env.example .env   # заполните токен и id
npm start
```

## Синхронизация с веб-версией

`src/seed-data.json` — снимок ростера и истории игр на момент создания
бота (тот же, что в `football-heroes-live.html`). После первого запуска
бот хранит свою собственную копию в SQLite и дальше живёт независимо от
веб-версии — правки в одном месте не попадают в другое автоматически.
Если нужно наладить постоянную синхронизацию (например, чтобы бот и
веб-страница читали одну и ту же базу) — это отдельная следующая задача:
веб-часть тогда тоже должна переехать с localStorage на этот же бэкенд.
